### 1.1 reading=0 的異常是長時間斷供與死錶

以「建築內連續 0 讀數的區塊（run）」切開（列在建築內為嚴格逐時且時間排序，已驗證：連續列 +1 小時的比例 = 1.0000）：

- 共 14,466 個 zero-run。其中**只有 718 個（5.0%）整段為異常，卻裝了 78,450 個 zero 異常小時 = 全部 80,776 個 zero 異常的 97.1%**。
- 13,707 個（94.8%）整段為正常，僅佔 85,288 小時。41 個（0.3%）為混合。
- 按 run 長度看該長度內小時的異常比例：

| run 長度 | run 數 | zero 小時數 | 該區間小時的異常比例 |
|---|---|---|---|
| 1h | 6,801 | 6,801 | 5.2% |
| 2–3h | 3,696 | 8,678 | 2.4% |
| 4–24h | 3,505 | 32,781 | 6.2% |
| 1–7d | 363 | 22,902 | 33.2% |
| **>7d** | **101** | **98,224** | **71.9%** |

　→ 長度 >7 天的 zero-run 只有 101 段，卻佔 98,224 個 zero 小時，其中 71.9% 為異常
　　（≈70.6k 小時 = 全部 zero 異常的 **87%**）。最長 zero-run = 8,051 小時（335 天）。
　→ **短暫的 0 多為合法（熱水本就關閉）；超過一週的 0 有 71.9% 為異常。**

- **hour-of-day 對 reading=0 幾乎沒有資訊量**：24 個小時中「zeros 裡異常的比例」只在 **45.7% ~ 51.1%** 之間變動（全距 5.5pp）。
  分辨「該有讀數卻是 0」與「合法的 0」，可用的訊號是 run 長度、季節與建築脈絡。

### 1.2 reading≠0 的異常是卡住的錶與讀數掉落

- **44.1%** 的非零異常列位於「連續 ≥3 個完全相同讀數」的區塊內，正常列只有 **16.8%**。
  相同值 run 長度 p90：異常 78h vs 正常 5h。
- 以各建築自身非零讀數的 robust z =（reading − 該建築中位數）/ 該建築 IQR：

| | p05 | p25 | median | p75 | p95 | %z>3（尖峰） | %z<−1（掉落） |
|---|---|---|---|---|---|---|---|
| 異常 | −1.35 | −0.34 | −0.00 | −0.00 | 1.72 | 3.1% | **11.3%** |
| 正常 | −0.79 | −0.29 | 0.00 | 0.61 | 2.00 | 2.6% | 1.9% |

　→ 尖峰比例兩者幾乎相同（3.1% vs 2.6%）；差別在**掉落**（11.3% vs 1.9%，6 倍）與**中位數附近的點質量**（p50、p75 同為 −0.00，符合「卡在某個固定值」）。
　→ 分布與正常列高度重疊，reading≠0 子集 PR-AUC 偏低可歸因於此。

### 1.3 結構極度不均勻

- 73 棟建築中，zeros 全為正常的有 7 棟、zeros 全為異常的有 16 棟、混合的 45 棟。
- 「該建築的異常有多少比例落在 reading=0」：中位數 75.7%，17 棟為 100%，4 棟為 0%。
- **非零異常高度集中**：`building_id=1241`（Healthcare）一棟就有 5,198 個非零異常 = **全部 9,915 個的 52.4%**；
  前 5 棟佔 66.4%，前 10 棟佔 76.0%；73 棟中只有 48 棟有任何非零異常。
  1241 只佔 hot-water 列數的 1.4%（8,765 列）。
- primary_use 層面：Healthcare 的 `%anom | reading≠0` 為 32.6%，其餘用途皆 0.3%–4.6%。

### 3.3 F1 的基準線與最佳閾值（`f1_context.py`）

F1 的絕對值在兩半之間完全不可比，因為「無技巧上限」（全部標記，precision=盛行率、recall=1，
`F1 = 2π/(1+π)`）隨盛行率劇烈變動：

| 子集 | 盛行率 π | 無技巧 F1₀ | lift 天花板 = 1/F1₀ |
|---|---|---|---|
| 合併熱水 | 14.26% | 0.2496 | 4.0× |
| reading = 0 | 47.69% | **0.6458** | **1.5×** |
| reading ≠ 0（全 73 棟） | 2.12% | **0.0416** | **24.0×** |
| reading ≠ 0（排除 1241） | 1.03% | 0.0204 | 49.1× |

**lift（F1/F1₀）同樣不可跨盛行率比較**：該比值的天花板為 `1/F1₀`，在 reading=0 為 1.5×、
在 reading≠0 為 24×，可達範圍相差 16 倍（本文件與報告頁的早期版本曾據此下結論，已更正）。
可跨盛行率比較的量為上限固定於 1 的 skill score `(F1−F1₀)/(1−F1₀)`，或隨機恆為 0 的 MCC。

正規化後（K=725，Tree，用 max-F1；`f1_alternatives.py`）：

| 子集 | max-F1 | lift | **F1 skill** | **max-MCC** | AP gain |
|---|---|---|---|---|---|
| 合併熱水 | 0.772 | 3.1× | 0.697 | 0.735 | 0.794 |
| reading = 0 | 0.801 | 1.2× | **0.440** | 0.611 | 0.745 |
| reading ≠ 0（全 73 棟） | 0.458 | 11.0× | **0.435** | 0.505 | 0.370 |
| reading ≠ 0（排除 1241） | 0.727 | 35.7× | **0.721** | 0.734 | 0.733 |

→ 正規化後兩半的技巧水準**相當**（F1 skill 0.440 vs 0.435）。直覺讀法（0.78 優於 0.32）與
lift 讀法（非零半為基準的 11 倍）都被此結果排除。
→ 不同正規化給出不同排序（lift 偏袒低盛行率、skill/MCC 較中性、AP gain 偏向高盛行率），
單一純量無法承擔跨子集比較。**在所有正規化下一致的是：排除 1241 後的非零那半
（0.721 / 0.734 / 0.733）與合併集同級，含 1241 的版本為 0.435 / 0.505 / 0.370 ——
§4.3 的結論不依賴正規化選擇。**
→ 文獻慣例（供撰稿時引用）：主指標用 PR-AUC / AP 並明講隨機基準 = π（Davis & Goadrich, ICML 2006；
Saito & Rehmsmeier, PLoS ONE 2015）；以 MCC 取代 F1（Chicco & Jurman, BMC Genomics 2020）；
需要跨盛行率可比的 PR 摘要用 PR-Gain / AUPRG（Flach & Kull, NeurIPS 2015）；
再加上固定告警預算下的 precision@k。本專案主圖本來就是 PR-AUC，這個選擇是對的。

max-F1（掃過所有可實現閾值，`F1(k) = 2·TP(k)/(k + Npos)`，候選點取 tie-group 末端）：

| K | reading≠0：F1@0.50 T/P | max-F1 T/P | Tree headroom | 最佳閾值 T/P | Tree 在該點 P/R |
|---|---|---|---|---|---|
| 50 | 0.248 / 0.188 | 0.288 / 0.237 | +0.040 | 0.45 / 0.52 | 0.391 / 0.337 |
| 100 | 0.353 / 0.267 | 0.412 / 0.311 | +0.058 | 0.67 / 0.65 | 0.653 / 0.304 |
| 200 | 0.388 / 0.313 | 0.424 / 0.362 | +0.036 | 0.64 / 0.73 | 0.643 / 0.318 |
| 400 | 0.369 / 0.355 | 0.451 / 0.407 | +0.082 | 0.75 / 0.76 | 0.754 / 0.323 |
| 725 | 0.324 / **0.354** | **0.458** / 0.426 | **+0.134** | 0.75 / 0.78 | 0.746 / 0.331 |

→ Tree 的 max-F1 單調上升：0.288 → 0.412 → 0.424 → 0.451 → 0.458。K=725 的「TabPFN 反超」
（F1@0.50 0.354 vs 0.324）在 max-F1 下**反轉回來**（0.426 vs 0.458）。分數分布隨 K 整體上移，
同一條 0.50 越來越寬鬆，於是在非零列多標卻沒多抓到。

（max-F1 0.727，只標記 0.79% 的列）。

**拆到逐建築後，季節性表現為組成效應（§4.4 的同一類問題）：**

| 模式 | 兩季都可評分 | 符合 | p(sign) | 逐建築差值中位數 |
|---|---|---|---|---|
| A：r0 gap 夏 > 冬 | **1 / 73** | 0 / 1 | 1.00 | −0.183 |
| B：rN gap 冬 > 夏 | 24 / 73 | 10 / 24（42%） | 0.54 | +0.000 |
| **機制：P(異常\|0) 夏天低於冬天** | 21 / 73 | **2 / 21（10%）** | **2.2e-4** | — |

→ 模式 A **無法檢定**:零讀數率從 1 月 11.3% 升到 8 月 34.7%,一棟建築的 0 幾乎只集中在其中一種季節,
  兩季都有足夠兩類樣本的只有 1 棟。
→ 模式 B **可檢定且不成立**（42%,p=0.54,中位數 0.000）。且冬季 27 棟的 rN AUC 幾乎全是 1.000（兩模型皆然）,
  因為 1–2 月每棟平均只有約 22 個非零異常且都極端 —— 沒有難度可區分模型。
→ **唯一顯著的是機制那列,而且方向是反的**:合併 P(異常|0) 冬 57.6% → 夏 35.5%,
  但逐建築 **19/21 棟是夏天更高**。典型 Simpson's paradox:夏天更多建築開始出現零讀數,
  而新加入者的 0 大多合法,**合併比率因此被組成拉低**；每棟建築內部的難度並未下降。
→ 合併量的形狀由組成決定，其成因見 §4.4；此處不再重述。
→ 個案（報告頁圖 3a）:building 167 整個夏季 7–8 月,1,062 小時為 0（744 異常 / 318 正常）,
  Tree AUC 0.964 vs TabPFN 0.876（gap +0.088）。夏季 reading=0 可評分的 14 棟中 Tree 領先 10 棟,
  該棟 gap 落在該組中段。逐建築離散度大：同季最好 +0.183、最差 −0.388。

### 3.5 0.50 的偏差源於平衡 context 的 prior shift（`f1_alternatives.py`）

**context 是 25,000 異常 / 25,000 正常 = 50% 先驗，評估盛行率卻是合併 14.26%、reading≠0 2.12%。**
分數因此系統性高估。K=725 Tree 的校準（分數分箱 → 箱內平均預測 vs 箱內實際異常率）：

| 分數區間 | 合併：預測 / 實際 | reading≠0：預測 / 實際 | reading≠0 偏差 |
|---|---|---|---|
| 0.4–0.5 | 0.450 / 0.176 | 0.454 / **0.031** | +0.423 |
| **0.5–0.6** | 0.548 / 0.168 | **0.547 / 0.030** | **+0.517** |
| 0.6–0.7 | 0.648 / 0.259 | 0.643 / 0.079 | +0.564 |
| 0.7–0.8 | 0.754 / 0.444 | 0.745 / 0.214 | +0.531 |
| 0.9–1.0 | 0.958 / 0.863 | 0.968 / 0.929 | +0.039 |
| 整體 | 0.193 / 0.143（ECE 0.054） | 0.045 / 0.021（ECE 0.028） | — |

→ 在 reading≠0 上，分數 0.5–0.6 那一箱模型說 0.547、實際只有 **0.030**（高估約 18 倍）。
這是 0.50 一刀切下去 precision 崩掉的直接原因。
→ 先驗換算一致：50% 先驗的分數要對應 π 先驗下的 0.5 後驗，原始分數需為 `1−π` —— 合併 0.857、
reading≠0 **0.979**。實測 F1 最佳閾值（0.72 / 0.75）落在 0.50 與這兩個值之間，位置正確
（F1 比 accuracy 容忍更多 FP）。
→ 交叉檢查：對已校準分類器，F1 最佳閾值 ≈ max-F1/2（Lipton, Elkan & Naryanaswamy, ECML PKDD 2014）。
reading≠0 K=725 的 max-F1 = 0.458 → 若已校準應在 0.229，實測 0.746。差約 3 倍，與上面的高估一致。
→ **0.50 的偏差量由實驗設計（平衡 context 訓練、不平衡資料評估）決定，屬系統性偏差。**
部署用的操作點需在驗證集重調並按目標盛行率做先驗校正。§3.2 那張表因此宜作為診斷閱讀。

## 4. gap 落在哪裡

### 4.1 pooled AP 的精確分解（恆等式）

AP 的定義等價於「對每個正樣本取其自身分數為閾值時的 precision，再平均」。因此

```
AP_pooled = w0·C0 + wN·CN        w0 = 80,776/90,691 = 0.8907    wN = 0.1093
C_S = 該子集正樣本的 precision@own-threshold 平均
```

已對 sklearn 逐 cell 驗證（差 < 1e-9），差分同樣精確：`ΔAP = w0·ΔC0 + wN·ΔCN`（殘差 < 1e-12）。

| K | ΔAP（pooled，Tree−TabPFN） | w0·ΔC0（reading=0 正樣本） | 佔比 | wN·ΔCN（reading≠0 正樣本） | 佔比 | Tree 勝出的 seed |
|---|---|---|---|---|---|---|
| 50 | +0.0589±0.0279 | +0.0558±0.0268 | **95%** | +0.0032±0.0032 | 5% | 4/5 |
| 100 | +0.0634±0.0501 | +0.0613±0.0481 | **97%** | +0.0021±0.0027 | 3% | 3/5 |
| 200 | +0.0372±0.0270 | +0.0363±0.0272 | **98%** | +0.0009±0.0011 | 2% | 4/5 |
| 400 | +0.0856±0.0243 | +0.0859±0.0245 | **100%** | −0.0003±0.0015 | −0% | 5/5 |
| 725 | +0.0079±0.0048 | +0.0127±0.0051 | 73% | −0.0048±0.0005 | −27% | 3/5 |

## 5. 結論

1. **Tree 對 TabPFN 的 hot-water 優勢落在 reading=0 這一半。**
   - pooled PR-AUC 的差在 K≤400 有 95%–100% 來自 reading=0 的正樣本（精確恆等式分解）。
   - 逐建築不加權 sign test 下，reading=0 是**唯一在每個 K 都穩定偏 Tree** 的子集（+0.024 ~ +0.058 ROC-AUC；K=50–400 p ≤ 2.5e-3）。
   - 這個差是同棟建築內的排序差（§4.4）。

2. **差距最大的格子是 K=400。**
   reading=0 ROC-AUC：Tree 0.789→0.862（K=200→400），TabPFN 0.774→0.779。Tree 在 5/5 個 building seed 都贏，
   pooled PR-AUC 差 +0.0856±0.0243 為全表最大。context 列數在每個 K 固定 50,000，所以 K 只改變建築多樣性；
   TabPFN 在 K=400 對「增加的建築多樣性」沒有轉換出 reading=0 的增益，到 K=725 才追上（0.857）。
   （此處僅陳述觀察，機制尚待驗證。）

3. **reading≠0 上的模型差由一棟建築決定。**
   `building_id=1241`（Healthcare，1.4% 的列）獨佔 52.4% 的非零異常。排除它之後，reading≠0 的 pooled ROC-AUC 差
   在每個 K 都塌到 ±0.01 以內，包含 K=725 的 −0.064 → −0.004。逐建築看，Tree 在 K=725 的 reading≠0 仍贏 37/48 棟。

4. **判讀上，兩個子集是兩種不同的偵測任務。**
   - reading=0：分辨「長時間斷供 / 死錶」與「合法關機」。97% 的零異常在整段異常的 zero-run 裡；>7 天的 zero-run 有 71.9% 是異常，
     ≤3 小時的只有 2–5%。時段（hour）幾乎沒有資訊（45.7%–51.1%）。這是一個 **run-length / 時序脈絡**問題。
   - reading≠0：主要樣態是**卡住的錶（flatline）與讀數掉落**（尖峰方向 %z>3 為 3.1% vs 2.6%，
     幾乎無差；偏低方向 %z<−1 為 11.3% vs 1.9%；44.1% 的異常在 ≥3 個相同值的區塊內 vs 正常 16.8%）。
     分布與正常高度重疊。

## 6. 限制與後續方向

本次分析有五項限制，依影響範圍排序。

1. **非零那半的模型差距由單一棟建築決定。** building 1241 佔熱水列數 1.4%、佔非零異常 52.4%；
   移除後合併 reading≠0 的 ROC-AUC gap 在每個 K 都落在 ±0.01 內（K=725 由 −0.064 變為 −0.004）。
   該半的模型層面結論需在排除該建築後重新確認，後續實驗宜將其列為獨立分層（§4.3）。
2. **合併指標含可觀的跨建築成分。** reading=0 子集內 98.7% 的排序配對來自不同建築；
   夏季合併 gap +0.108 對逐建築中位數 +0.018，量級相差六倍。
   模型比較宜同時報告逐建築配對結果，或改用建築內分層指標（§4.4）。
3. **固定 0.50 的操作點受 prior shift 影響。** context 先驗 50%、評估盛行率 14.26%（非零半 2.12%），
   分數系統性高估：非零子集在 0.5–0.6 箱的預測值 0.547 對實際 0.030。reading≠0 的最佳閾值在
   0.64–0.76。部署前的操作點需在驗證集重調並依目標盛行率做先驗校正（§3.5）。
4. **兩個子集的指標絕對值不可跨半比較。** 盛行率 47.7% 對 2.12%，無技巧 F1 上限分別為 0.646
   與 0.042（相差 15 倍）；lift 形式的天花板也隨盛行率變動（1.5× 對 24×）。
   跨子集比較宜採 skill score、MCC 或 ROC-AUC（§3.3）。
5. **季節性目前只在族群層面成立。** 逐建築配對檢定受限於樣本：reading=0 兩季都可評分的建築僅
   1 棟，reading≠0 為 24 棟且方向符合者 10 棟（p = 0.54）。要把季節性提升為建築內部的機制主張，
   需要跨年度資料以取得同一棟建築的多個冬夏配對（§3.4）。

另外兩項不屬限制、但屬易被誤讀處：K=725 的 pooled ROC 與 pooled PR 方向不一致
（TabPFN ROC +0.003、PR −0.008）為加權結果 —— reading=0 佔 89.1% 的正樣本但僅 16.25% 的負樣本，
ROC 由負樣本主導、PR 由正樣本主導；同一操作點下的 R-precision 顯示 Tree 在 K=725 領先
+0.041±0.005（§3.6）。而排除 1241 後 reading≠0 的 PR-AUC 為 0.736（盛行率 1.03%）、
ROC-AUC 0.973，該半並不難以偵測。

  （如 `~/.cache/`），只把人類要讀的輸出放 `/mnt/c`。
- pandas 為 3.0.x，`series.astype("int64") // 10**9` 不再是 epoch 秒（Series 是
  `datetime64[us]`，會塌成 0）。改用 `series.astype("datetime64[s]").astype("int64")`。

## 附錄 A：長零讀數區塊的 run-level 判讀（次要問題）

**與主線的關係先講清楚。** 本文 §4 解釋的是 PR-AUC 的差距，而 PR-AUC 以正樣本加權、
逐小時計數：一段 500 小時的異常停機就是 500 個正樣本。本附錄改以**區塊**為單位
（每段一個分數、一個標籤），因此**不是關於 PR-AUC 的證據** —— 它回答的是另一個問題：
「一段長零讀數，模型能否判斷它是合法停機還是故障」。這個問題本身值得問，但它的答案
不能用來推論 PR-AUC，反之亦然。

改用 run-level 的理由：同一段停機內的小時近乎重複，hour-level 統計量的有效樣本數
遠低於名目 n。這對「判斷一段區塊」的問法是必要的；對 PR-AUC 則不適用，因為逐小時
加權正是 PR-AUC 的定義。

操作化：把每棟建築的序列切成連續 `reading=0` 的最大區塊；只留整段落在視窗內、長度
≥ MIN_LEN、且標籤純粹（全異常或全正常）的區塊；每個 run 的分數 = 該 run 內逐時分數
的平均；再算 run-level ROC-AUC。附 paired bootstrap 95% CI（對 run 重抽）、逐 cell
gap、drop-one-building jackknife。

夏季（6/7/8 月），K=400：

| MIN_LEN | runs（異常/正常） | Tree | TabPFN | gap | bootstrap 95% CI | 逐 cell |
|---|---|---|---|---|---|---|
| ≥ 24 h | 124（13 / 111） | 0.6909 | 0.9210 | **−0.2301** | [−0.383, −0.096] | Tree 領先 0/10 |
| ≥ 72 h | 54（8 / 46） | **0.4864** | 0.9212 | **−0.4348** | [−0.707, −0.170] | Tree 領先 0/10 |
| ≥ 168 h | 23（3 / 20） | **0.1667** | 0.8333 | **−0.6667** | [−0.905, −0.364] | Tree 領先 0/10 |

　在 ≥168 h 為 0.1667 —— 低於隨機，意即它系統性地把合法的長停機排在真實故障之前。
　gap 隨區塊長度單調擴大。
→ 穩健性同向：median 聚合 −0.247 / −0.459 / −0.733；K=725 −0.233 / −0.410 / −0.483
　（逐 cell 0/5）；jackknife 在 ≥24 h 的 gap 範圍 [−0.296, −0.158]，移除最有影響的
