## Required understanding summary

1. **E0 meter roles.** Steam is the principal stable empirical advantage; chilledwater is an observed but not stable advantage; electricity is the counterexample; hotwater is a supporting/context lever with no supported advantage (`S003`).
2. **C1 chilledwater conclusion.** `WITHIN_METER_MORPHOLOGY`: chilledwater's advantage exists only against its own negatives; it is negative against hotwater negatives. E0's “observed advantage but not stable” classification remains unchanged (`S004`).
3. **E4 result.** E4 froze and executed 24 TabPFN fits (`3 seeds × 4 cells × 2 scaler arms`) with 8 same-process repeats. Hotwater-negative support produced a large positive steam response beyond the matched fixed tree; hotwater-positive support was negative but not TabPFN-specific; the interaction was not established; scaler arms were null (`S006`, `S032`).
4. **E5 independent replication.** On a disjoint never-before-scored 192-row query, response replication and TabPFN-specific replication both passed. The negative-support effect was `+0.4049` AUC / `+0.5992` margin and the TabPFN-minus-tree gap `+0.0827` / `+0.1010` (`S007`–`S010`).
5. **E6 question.** E6 asks whether that response holds at natural prevalence on all odd-building holdout rows, using the same 24 E4 states. It is a new-state factorial confirmation on previously characterised rows, not an untouched holdout (`S011`, `S015`).
6. **Why E7 does not inherit 20k.** E4/E6's 20,000 rows define those controlled factorial states; the E6 throughput report explicitly treats it as the configuration being confirmed. Historical Full Tree used 2,708,308 downsampled fit rows. E7 may inherit the architecture and evidence controls without inheriting that intervention budget (`S012`, `A003`).
7. **Historical Full Tree baseline source.** Scores are field `ensemble` in `A001`, generated by `S028`; model/feature manifest is `A003`; per-meter table generation is `S029`. Identity is supplied by `A002`, because `A001.validation_raw_index` is internally inconsistent with its score order.
8. **Historical steam PR-AUC.** On canonical odd rows with `meter == 2`, `sklearn.metrics.average_precision_score(anomaly, ensemble)` is exactly `0.7708216687325591`, rounding to `0.7708` (`S029`, `A001`–`A006`). This is average precision, not trapezoidal PR-curve AUC.
9. **Tree components.** LightGBM, XGBoost, CatBoost, and HistGradientBoosting; each uses model seed 42, and the final score is their equal-weight probability mean (`S028`, `A003`).
10. **Split and odd-steam identity.** Fit is `building_id % 2 == 0`; holdout is `building_id % 2 == 1`. The holdout has 10,137,155 unique rows, 724 buildings, 16 sites and 637,397 anomalies. Steam is code 2 and has 1,350,609 rows, 48,888 anomalies, 162 buildings and 6 sites (`S015`, `S022`, `S027`, `A002`–`A006`).
11. **E7 comparison boundary.** The primary reference is the historical F4/137 Full Tree ensemble (`A001`, `S028`, `S029`). Any new strategy must preserve the odd holdout identity and report component and ensemble results rather than changing the reference.
12. **Avoiding a “more models naturally wins” explanation.** `A001` contains all four component vectors as well as their ensemble. E7 must expose component-level results and the equal-weight ensemble, and add a matched-compute/component-count control before attributing a gain to strategy rather than ensembling (`S028`, `A001`). Exact compute allocation belongs in the later frozen protocol.
13. **Avoiding training-row-count confounding.** The existing matched-context Tree pipeline requires byte-identical row IDs, order and label balance for the two model families. E7 inherits this matched-row rule and must separately report any full-capacity comparison (`S030`).
14. **Avoiding odd-label leakage.** Model/feature selection must use only even-building data; odd labels are read once for the frozen evaluation and audit. The raw-index split is building-disjoint and uniqueness-gated (`S024`, `S027`, `A002`–`A006`).
15. **Complete isolation from active E6.** E7 inherits no E6 states, partial scores, execution order, scalers, topology or TabPFN artifacts. This ingestion used only local tracked reports/frozen protocol copies and historical M3/M5 artifacts; it did not open active E6 output, inspect a terminal, or contact a remote host (`S011`–`S021`, `S039`).

## Canonical contracts

### Meter, cells and effects

- Meter map: electricity `0`, chilledwater `1`, steam `2`, hotwater `3` (`S022`).
- Anomaly label: `1` is a bad/anomalous meter reading and `0` is normal, assigned positionally after length, schema, default-index and unique `(building_id, meter, timestamp)` gates (`S024`, `A005`).
- Cell coding: first bit is hotwater-positive support; second bit is hotwater-negative support. Thus `00` excludes both, `01` includes only negatives, `10` includes only positives, `11` includes both (`S022`, `S032`).
- Positive-support main effect: `(y10 + y11 - y00 - y01) / 2`.
- Negative-support main effect: `(y01 + y11 - y00 - y10) / 2`.
- Interaction: `y11 - y10 - y01 + y00` (`S022`).
- Context seeds: `42, 123, 999`; scaler arms: `cell_specific`, `frozen_reference` (`S032`).

### F4/137 features

The exact ordered list is stored in `e7_source_map.json`. It is the 17 ordered
`BASELINE_FEATURE_COLS` followed by, for every ordered value in `SHIFTS`,
`lag_value_diff_{shift}` then `lag_value_ratio_{shift}`. The builder preserves
the original positional index in `__raw_index_carrier`, applies
`timestamp_merge`, restores the index, selects requested `raw_index` values in
that order, and returns `float32` (`S023`–`S026`). Metadata comes from
`building_metadata.csv`; labels from `bad_meter_readings.csv`; weather from
`weather_train.csv`; meter/building/timestamp/meter reading from `train.csv`
(`S024`).

### Historical Full Tree

- Split: even buildings fit, odd buildings holdout.
- Features: F4/137, `timestamp_merge`.
- Downsampling: repository `downsample_indices`, seeds `10, 20`; realised fit rows `2,708,308`.
- Scaling: `StandardScaler.fit_transform` on training rows, then transform holdout.
- LightGBM: `n_estimators=100`, `verbose=-1`, `random_state=42`.
- XGBoost: `n_estimators=100`, `eval_metric=logloss`, `verbosity=0`, `random_state=42`.
- CatBoost: `iterations=1000`, `verbose=false`, `random_seed=42`, `allow_writing_files=false`.
- HistGradientBoosting: `max_iter=100`, `random_state=42`; only this component receives `np.nan_to_num(..., nan=0)`.
- Ensemble: arithmetic mean of the four probability vectors.
- Metric: `average_precision_score`; table output rounds to four decimals (`S028`, `S029`, `A003`).

## Resolved conflicts

1. **Baseline index trap.** `A001.validation_raw_index` is sorted, while its labels and score vectors use canonical scoring order. It is not used as a row key. `A002.raw_index` supplies canonical order; `A001.anomaly == A002.anomaly == A005[raw_index]` element-wise. This follows the explicit gate in `S029`.
2. **E6 identity wording.** The rows are not untouched; only the factorial states are new (`S011`, `S015`).
3. **Tree cross-platform drift.** E5's laptop environment is the only bit-exact environment; gpu-host Tree output is prohibited. The 24/24, 352/352, zero-tolerance gate and re-derivation path remain authoritative (`S035`–`S038`).
4. **E6 cost estimate.** The old 330 rows/s estimate is superseded by the direct 1,414 rows/s probe; this is execution provenance only and is not inherited by E7 (`S012`).
5. **20k meaning.** It is the frozen E4/E6 context condition, not a Tree capacity ceiling (`S006`, `S011`, `S012`, `A003`).

There are **no unresolved load-bearing conflicts**.
